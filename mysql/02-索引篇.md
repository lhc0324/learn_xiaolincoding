## 2.1 索引常见面试题

**状态**:✅

**我学到的**:

**_为什么mysql innoDB 选择 b+ 树作为索引的的数据结构？_**

- vs b : b+树只有叶子节点存储数据，根节点只存储索引，b树根节点和叶子节点都存储数据，这样b+树存储相同数据量的情况，b+树的树高比b树低。b+树叶子节点使用双向链表，适合范围查询，b树做不到这点。
- vs 二叉：b+树随着数据量的增加可以维持在3-4层，但是二叉树树高会很高，所进行的i/o操作也就更多
- vs hash : b+树可以做范围查询，但是hash做不了范围查询，hash树只有等值查询特别快

**_什么时候适用索引？_**

- 字段具有唯一性
- 经常用来order by或者group by
- 经常用来where查询的

**_什么时候不需要创建索引？_**

- where order by group by用不到的
- 表中存在大量重复数据
- 数据量很小的情况
- 数据经常更新的情况

**_什么时候索引会失效？_**

- 当我们使用左或者左右模糊的查询的时候
- 当我们在查询的过程中做了计算、函数、类型转换的时候
- 联合查询不符合最左优先的时候
- where子句中or之前的是索引列，or之后的不是索引列

**_有什么优化索引的方法？_**

- 前缀索引优化
- 覆盖索引优化
- 主键索引最好是自增的
- 防止索引失效

## 2.2 从数据页的角度看 B+ 树

**状态**:✅

**我学到的**:
InnoDB 以 16KB 数据页为单位读写。页内记录用单向链表串联，并另设页目录（槽/分组），因主键有序，可在页内二分查找；页与页之间用双向链表连接，物理上不连续、逻辑上连续。

为快速定位"记录在哪一页"，InnoDB 用 B+ 树做索引，每个节点就是一个数据页。叶子节点存什么，决定了索引的类型：

- 叶子存实际数据 → 聚簇索引，一个表只能有一个
- 叶子存主键值 → 二级索引，一个表可以有多个

用二级索引查询时：

- 需要的列在二级索引的叶子上能找到 → 索引覆盖
- 找不到 → 先在二级索引拿到主键值，再回聚簇索引取数据行

## 2.5 索引失效有哪些?

**状态**:✅

**我学到的**(六种场景):

- 出现左或者左右模糊查询的时候，比如like"%哈哈""%哈哈%"的情况
- 查询条件中对索引使用函数
- 查询条件中对索引进行运算
- 联合查询不满足最左原则
- where中or之前的索引列有效，or之后的索引列失效
- mysql中当将字符串类型的和int类型的数据进行比较的时候，会自动将字符串转换成int类型，当字符串是索引列时，相当于将索引列调用函数转换成int类型，违反了第二个场景，就会失效
